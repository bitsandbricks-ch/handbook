# Ansible

For hosts that aren't in a cluster: VMs, appliances, Proxmox nodes, home servers. Profile `infra`.

## Layout

```
ansible/
├── ansible.cfg               # inventory path, roles path, no host key skipping
├── requirements.yml          # collections and roles, pinned to exact versions
├── inventory/                # generated by Labdex where possible; hand-written hosts only for the rest
│   └── group_vars/  host_vars/
├── playbooks/<purpose>.yml   # one playbook per job: base, patch, docker-host, backup
└── roles/<role>/             # tasks, handlers, defaults, templates, meta, molecule/
```

## Rules

- **Idempotent.** A second run changes nothing. `command` and `shell` only when no module
  exists, always with `creates:`, `removes:` or `changed_when:`.
- **Check first.** Every run against production starts with `--check --diff`; the diff goes in
  the MR. A role that can't run in check mode says why in its README.
- **Small blast radius.** `serial:` for anything that restarts services; `--limit` to one host
  before the group; `become: true` per task or role, not for the whole play.
- **Variables:** defaults in `roles/<role>/defaults/`, environment values in `group_vars/`,
  nothing hard-coded in tasks. Names are prefixed with the role (`docker_host_users`).
- **Secrets:** SOPS-encrypted vars files (same age keys as Flux) or the Labdex vault;
  `no_log: true` on tasks that touch them. No Ansible Vault passwords in the repo or CI logs.
- **Pinned:** collections and roles pinned in `requirements.yml`; Renovate updates them.
- **Tagged:** every task in a role has the role's tag, so `--tags` works.
- **Lint:** `ansible-lint` with the `production` profile in pre-commit and CI.
- **Tests:** roles that others reuse have a Molecule scenario; the rest are tested with
  `--check` against a test host.

## Running

- Runs go through a reviewed MR, like Flux. The run after merge is started from CI or from Labdex
  (which keeps the log); never from a laptop against public production without Mike's go-ahead.
- Patching follows the Labdex patch flow: drain, patch, reboot when needed, health check, uncordon,
  one host at a time.

> **Avoiding conflicts:** one role per concern, one playbook per job, vars per group; the
> inventory is generated, so nobody hand-edits the same host list.
